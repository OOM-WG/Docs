## 依赖

<Tip>
  构建工具会使用 [NGA SDK](https://app.niggergo.work/nga/shell) 在构建时自动集成 Shell Utils，自动混淆加密
  `action.sh`、`customize.sh`、`nga-utils.sh`
</Tip>

- [Android NDK](https://developer.android.google.cn/ndk)
- [Go](https://golang.google.cn)
- [Garble (可选)](https://github.com/burrowers/garble)

<Warning>本地构建需要至少有 `ksh` 或者语法特性更多的 Shell 解释器！否则 Shell 加密无法运行，不可使用 `POSIX` Shell！</Warning>

## 使用方法

<Tabs>
  <Tab title='GitHub Action'>
    <Steps>
      <Step title='新建文件夹'>前往示例仓库通过模板生成新项目</Step>
      <Step title='修改代码'>修改模块项目代码</Step>
      <Step title='构建模块'>通过 GitHub Action 手动或自行修改 Workflow 来实现构建模块</Step>
    </Steps>
  </Tab>
  <Tab title='本地构建'>
    <Steps>
      <Step title='新建文件夹'>前往示例仓库通过模板生成新项目</Step>
      <Step title='下载代码'>将本项目与模块项目克隆至本地</Step>
      <Step title='修改代码'>修改模块项目代码</Step>
      <Step title='构建模块'>通过 Go 运行本项目的构建工具来实现构建模块</Step>
    </Steps>
  </Tab>
</Tabs>

### 注意事项

- 模块目录
  - `action.sh` 的支持范围是: ShiroSU 默认支持/Magisk 27008+/KernelSU 1.0.2+/APatch 11039+
    <Tip>低版本不支持该按钮，开发者应避免不支持而是建议使用者脱离啃老或建议非 GKI 原版 KSU 使用者转向其他分支</Tip>
  - `post-mount.sh`、`boot-completed.sh` 仅在 ShiroSU/KernelSU/APatch 支持，
    但 Magisk 可在 `service.sh` 内主动执行 `boot-completed.sh`
  - `META-INF` 在仅支持 ShiroSU/KernelSU/APatch 时无需包含
  - `zygisk`、`bin` 会通过 `c++_native`/`go_native` 中的目录自动添加，如有需要，也可自行添加
- C++ 项目
  - _项目名称_ 必须与 `Android.mk` 中的 `LOCAL_MODULE` 相同，即构建后的文件名称
    - `Android.mk` 如果配置以 `BUILD_EXECUTABLE` 构建，将自动把编译后文件移动至模块目录的 `bin/<项目名称>/<架构>.bin`，
      如果配置以 `BUILD_SHARED_LIBRARY` 构建，将自动把编译后文件移动至模块目录的 `zygisk/<架构>.so`
- Go 项目
  - _项目名称_ 必须与 `go.mod` 中的 `module` 值的最后名称相同，即构建后的文件名称
    - `arch` 按行输出要构建的架构，架构以 Go 支持的为准 (例如使用 `amd64` 而非 `x86_64`)
- `changelog.md`、`update.json` 等文件可按需自定义名称、路径

<Warning>后续会重构项目架构，使其基于 `FVV` 配置</Warning>
