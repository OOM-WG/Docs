## 对于 `SSU` 项目开源说明

<Card icon="github">
  <p>`SSU` 项目为 `O.O.M. W.G.` 的隶属项目，其 @白彩恋 为用户空间实现的开发者，@Linso 为内核空间实现的开发者，对于 SSU 文档内容为 @YumeYuka 编写并与其他成员协作优化。</p>
  
  <ul>
    <li>`SSU` 管理器 本身可作为<code>模块管理器</code>使用，内核空间实现由于 @Linso 私人原因开发进度缓慢</li>
    <li>`SSU` 已开源部分配置以及一些核心组件，详见 <Link href="https://github.com/OOM-WG/ShiroSU">ShiroSU 仓库</Link> 与 <Link href="https://github.com/orgs/OOM-WG/repositories">OOM-WG 组织</Link>。</li>
    <li>管理器全部代码由 @白彩恋 编写，@YumeYuka 参与优化部分页面</li>
    <li>用户空间代码已全部规避 `GPL` 协议，包括 `WebUI` 实现</li>
    <li>对于内核空间代码由 @Linso 完成，开源程度由 @Linso 完善度决定</li>
    <li>对于文档部分，文档使用 `vitepress` 驱动，并且也已经开源</li>
  </ul>
  
  <p>对于具体的开源方向，`SSU` 项目将主要开源在开发过程中形成的较为成熟的框架/工具等，开源核心源码并不是首要目的。</p>
  
  <p>`SSU` 的界面是使用第三方库开发的，由于第三方库的欠缺，在部分 UI 底层上的问题，`SSU` 的开发者暂时无力解决。</p>
</Card>

## 对于 SSU == KernelSU Fork

<Callout type="caution">
评价：玩 `KernelSU Next` 玩的
</Callout>

<Card title="技术实现说明">
  <p>`O.O.M. W.G.` 成员帖子中明确注明非 `KernelSU` 分支，盲目得出结论未免为时过早，`SSU` 仍在开发中，root 实现需要等待内核空间实现代码开发进度。</p>
  
  <p>尽管 `SSU` 同样是基于内核的 root 实现，但这并不代表项目之间存在直接关联。在某些技术实现上有重叠是很正常的现象，但过度解读这种重叠并无意义。</p>
  
  <Accordion>
    <AccordionItem title="技术澄清">
      <p>有些人说是 `KernelSU` API 套壳，但是 `KernelSU` 并没有任何通用 API，`SSU` 的所有代码都是针对各种有模块实现的 root 实现而进行的通用开发，并且 `SSU` 主体是一个 `Kotlin` 项目，绝大部分代码都是由 `Kotlin` 的 `JVM/Native` 实现的，仅有少部分代码由于 `Kotlin` 无法实现，是由 `C++` 实现的，而其他 root 实现大多都采用 `Kotlin/Java` 开发软件，`C++/Rust` 开发用户空间工具，说 `SSU` 是 `Fork` 纯属无稽之谈。</p>
    </AccordionItem>
  </Accordion>
  
  <p>并且，如果跟随着 `SSU` 的历史更新并深究具体更新内容，就能发现 `SSU` 逐渐实现了 `SU CLI`、通用操作、通用模块安装等内容，只不过这些内容都是为了后续内容而铺垫，并没有写进更新日志。</p>
</Card>
